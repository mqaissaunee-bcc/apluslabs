Security & Privacy

Windows ships with an antivirus, a firewall, and two kinds of encryption, and most users never touch their settings. Why this lab matters

The built-in security tools are good enough that many organizations rely on them, but only if they're configured and checked. This lab covers the three layers.

Microsoft Defender Antivirus finds and removes malware; the offline scan reboots into a clean environment to catch malware that hides while Windows is running. Windows Defender Firewall decides which traffic gets in and out, per program, port, and network profile; you'll write a custom rule and prove it works with ping. Encryption protects data if a device is lost or stolen: EFS encrypts individual files for one user, and BitLocker encrypts an entire drive.

Encryption has one hard rule: back up the key. Lose the EFS certificate or the BitLocker recovery key and the data is gone for good.

Walkthrough

Task 1: Malware scans (Win10)

1Open the security dashboard

Log in to Win10. Search for Windows Defender and open Windows Defender Security Center. The Home page shows the status of each area: a green check is good, a yellow ! needs attention.

2Look at the scan types

Click Virus & threat protection. Quick scan checks the places malware usually hides. Click Run a new advanced scan to see Full scan, Custom scan, and Windows Defender Offline scan.

ScreenshotThe advanced scan options page.

3Start an offline scan

Select Windows Defender Offline scan > Scan now > Scan and accept UAC. Windows signs you out and restarts into the Defender environment. With no internet it skips the definition update and starts scanning. After a few minutes, click Cancel scan; Windows then boots normally.

When to use the offline scan

Rootkits and some other malware hide from scanners while Windows is running. Booting into a separate environment means the malware isn't loaded, so the scanner can see and remove it.

Task 2: Health report (Win10)

4Read device health

Sign back in. Open the Windows Defender icon from the hidden tray icons, then Device performance & health. Check the Health report: storage capacity, device drivers, and apps and software. Green is good, yellow is a recommendation, red is a warning.

ScreenshotThe Device performance & health report.

Task 3: Firewall profiles (Win10)

5Look at the Private profile

Click Firewall & network protection > Private network. Note the switch that turns the firewall on or off for this profile. Click back and close the window.

Task 4: Allowed apps (Win10)

6Open the firewall in Control Panel

Right-click Start > Run, enter Control Panel, and open System and Security > Windows Defender Firewall. Click Turn Windows Defender Firewall on or off to see the per-profile settings, then go back.

7Allow Windows Media Player on Private networks

Click Allow an app or feature through Windows Defender Firewall (click Change settings if the list is greyed out). Select Windows Media Player > Details, read it, and click OK. Check the box beside Windows Media Player: Private is checked automatically.

8Add an app that isn't listed

Click Allow another app > Browse, go to C:\Program Files\Windows Photo Viewer, select ImagingDevices.exe, and click Open > Add. Imaging Devices Console appears, allowed on Private.

ScreenshotThe allowed apps list with Windows Media Player and Imaging Devices Console allowed.

9Remove it again

Select Imaging Devices Console > Remove > Yes, then OK.

Task 5: Firewall rules (Win10 and Win7)

10Confirm ping works both ways

In Windows Defender Firewall, click Advanced settings to open Windows Defender Firewall with Advanced Security. Open cmd on Win10 and on Win7 and test:

On Win10
ping 192.168.1.7
On Win7
ping 192.168.1.10

Both succeed.

11Find the built-in ping rule

On Win10, click Inbound Rules and find File and Printer Sharing (Echo Request - ICMPv4-In) for the Private profile. Right-click it: it's enabled, which is why Win7 can ping Win10. Leave it enabled.

12Create a rule that blocks ping

Right-click Inbound Rules > New Rule and set:

Wizard stepChoose
Rule typeCustom
ProgramAll programs
Protocol and PortsICMPv4 > Customize > Specific ICMP types > Echo Request
ScopeDefaults
ActionBlock the connection
ProfileDefaults (Domain, Private, Public)
NameBlock Incoming ICMPv4 Echo Requests

ScreenshotThe new Block Incoming ICMPv4 Echo Requests rule in the Inbound Rules list.

13Test the block

On Win7, run ping 192.168.1.10 again. It now times out, because a block rule beats the built-in allow rule.

ScreenshotWin7's ping to Win10 timing out.

14Disable the block and test again

On Win10, right-click Block Incoming ICMPv4 Echo Requests > Disable Rule. On Win7, ping 192.168.1.10 succeeds again.

The PDF has this backwards

It says ping fails after you disable the block rule. It's the reverse: ping fails while the block rule is enabled and works again once you disable it.

Task 6: Encrypting File System (Win7)

15Encrypt a file

On Win7, create a text file on the desktop named encrypted. Right-click it > Properties > Advanced, check Encrypt contents to secure data, and click OK twice. Choose Encrypt the file only and click OK. The file name turns green.

16Back up the encryption key

Click the Back up your encryption key notification > Back up now (recommended). In the Certificate Export Wizard, keep the default format (a .pfx file), set the password to mypassword, name the file EFS-key, and click Finish. Note where it saved.

ScreenshotThe Certificate Export Wizard's final page showing the EFS-key file location.

17Test access as another user

Double-click encrypted: it opens for sysadmin with no extra prompt. Now Switch user to user1 (SuperSecret), browse to C:\Users\sysadmin\Desktop (enter Train1ng$ if asked), and open encrypted. Access is denied.

ScreenshotThe access denied message when user1 opens the encrypted file.

Log off user1.

Task 7: BitLocker without a TPM (Win10)

18Allow BitLocker with a password

On Win10, open gpedit.msc and go to Computer Configuration > Administrative Templates > Windows Components > BitLocker Drive Encryption > Operating System Drives. Double-click Require additional authentication at startup, select Enabled, and click OK. Make sure Allow BitLocker without a compatible TPM is checked in that setting's options.

19Turn on BitLocker

Open Control Panel > BitLocker Drive Encryption > Turn on BitLocker. Choose Enter a password and enter Train1ng$ twice.

20Save the recovery key

Choose Print the recovery key, select Microsoft XPS Document Writer, and save it as EFS-Recover in Documents.

Recovery key handling

On real devices, save the recovery key to the Microsoft account, Active Directory or Entra ID, or a secure file stored off the encrypted drive. The 48-digit key is the only way in if the password is forgotten or the hardware changes.

21Encrypt

Choose Encrypt used disk space only, then New encryption mode. Uncheck Run BitLocker system check and click Start encrypting. Click the notification to watch progress and Close when it finishes.

ScreenshotBitLocker Drive Encryption showing C: with BitLocker on.

Task 8: Check and turn off BitLocker with PowerShell (Win10)

22Check status

Search for PowerShell ISE, right-click it > Run as administrator, and run:

manage-bde -status

C: shows as fully encrypted with XTS-AES 128.

23Decrypt

Disable-BitLocker -MountPoint "C:"
manage-bde -off C:
manage-bde -status

Decryption continues in the background; run manage-bde -status again to watch the percentage drop. Type exit when it's done.

Typed straight from the PDF?

The PDF shows manage-bde –status with an en dash. Use a normal hyphen.

Screenshotmanage-bde -status showing decryption in progress or complete.

The lab is complete.

On the A+ exams

Core 2: Security

Core 2 (220-1202) covers Windows Security and Defender Antivirus, Windows Defender Firewall (profiles, rules, allowed apps, ports), EFS and BitLocker (including BitLocker To Go and recovery keys), edition differences, malware types and the malware removal procedure, and data-at-rest encryption as a best practice.

High-yield facts

  • EFS encrypts files per user; BitLocker encrypts whole volumes; BitLocker To Go encrypts removable drives.
  • BitLocker needs Pro or higher; it prefers a TPM; back up the 48-digit recovery key.
  • Offline scans catch malware that hides while Windows is running.
  • Firewall block rules override allow rules; outbound traffic is allowed by default.
  • Malware removal: investigate, quarantine, disable System Restore, remediate, schedule, re-enable restore, educate.
  • manage-bde -status checks BitLocker; wf.msc opens the advanced firewall.

Check yourself

1. A laptop with sensitive data might be stolen. EFS or BitLocker?

BitLocker. It encrypts the whole drive, so nothing is readable without unlocking the device. EFS only protects specific files from other users.

2. A user reinstalled Windows and now can't open EFS-encrypted files from their old drive. What would have prevented this?

Exporting the EFS certificate and private key (.pfx) before the reinstall, then importing it afterward.

3. You create an inbound rule blocking ICMPv4 Echo Request, but the built-in Echo Request allow rule is also enabled. Can the PC be pinged?

No. Block rules take precedence over allow rules.

4. Why disable System Restore during malware removal?

Restore points can contain the malware, so restoring one later could reinfect the PC. Re-enable it and create a clean restore point after cleanup.

5. Which command shows whether a drive is encrypted with BitLocker?

manage-bde -status (or Get-BitLockerVolume in PowerShell).

Cheat sheet

Defend

  • Windows Security: quick, full, custom, offline scans
  • wf.msc advanced firewall
  • Block beats allow; profiles: Domain, Private, Public
  • netsh advfirewall show allprofiles
  • Malware: investigate, quarantine, disable restore, remediate, schedule, re-enable, educate

Encrypt

  • EFS: per file, per user; export the .pfx
  • BitLocker: whole volume, Pro+, TPM preferred
  • BitLocker To Go: USB drives
  • Save the 48-digit recovery key off the drive
  • manage-bde -status, -on, -off
