== overview | Why this lab matters
Scripts turn a checklist into one command. A technician uses them to gather information from many PCs the same way, map drives at sign-in, install software, clean up temp files, or restart a stuck service on a schedule (Lab 02's Task Scheduler can run any of these).
This lab writes one job, "report this PC's OS, hardware, and network," in the three scripting languages you're most likely to meet: **batch** (`.bat`) for classic Windows, **PowerShell** (`.ps1`) for modern Windows administration, and **Bash** (`.sh`) for Linux. Comparing them line by line shows that the logic is the same and only the syntax changes.
You'll also meet each platform's guardrail: PowerShell's **execution policy** and Linux's **execute permission**.

== walkthrough | Walkthrough
## Task 1: A Windows batch file <<1>>
@@ Win10
### Look at the available commands
Open the **Win10** console, click the splash screen, and sign in as `sysadmin` with `Train1ng$`. Click the search icon, type `cmd`, and open **Command Prompt**. List the built-in commands one page at a time:
```C:\Users\sysadmin>
HELP | MORE
```
Press [[Space]] for the next page and [[Q]] to quit. Find `echo`, `findstr`, `rem`, and `systeminfo` (`wmic` is a separate program, so it isn't in this list).
### Write the script in Notepad
Click the search icon, type `Notepad`, and open it. Type (or copy) the script:
```file Sysinfo.bat
@ECHO OFF
:: This batch file reveals OS, hardware, and networking configuration.
TITLE My System Info
ECHO Please wait... Checking system information.
:: Section 1: OS information.
ECHO ============================
ECHO OS INFO
ECHO ============================
rem findstr is used for searching for a text string in files. For more inline information, you can enter findstr /? at the command prompt.
systeminfo | findstr /c:"OS Name"
systeminfo | findstr /c:"OS Version"
systeminfo | findstr /c:"System Type"
:: Section 2: Hardware information.
ECHO ============================
ECHO HARDWARE INFO
ECHO ============================
systeminfo | findstr /c:"Total Physical Memory"
wmic cpu get name
:: Section 3: Networking information.
ECHO ============================
ECHO NETWORK INFO
ECHO ============================
ipconfig | findstr IPv4 >> info.txt
ipconfig | findstr IPv6 >> info.txt
PAUSE
```
!stuck Keep wrapped lines whole | The PDF wraps the long `rem` line onto two lines. Type it as **one** line. If `information, you can enter...` lands on its own line, cmd tries to run it as a command and prints an error.
### Save it as a .bat file
Choose **File > Save As**, go to `C:\Users\sysadmin`, set **Save as type** to **All Files**, and name it `Sysinfo.bat`.
!stuck Where people get stuck | If Save as type stays on **Text Documents**, Notepad saves `Sysinfo.bat.txt`, which won't run. Choose All Files, or put the name in quotes: `"Sysinfo.bat"`. Run `dir` to check.
### Run it
```C:\Users\sysadmin>
dir
Sysinfo.bat
```
Watch the OS and hardware sections print on screen. Press any key at `PAUSE`. The network lines don't appear because `>>` sent them to a file:
```C:\Users\sysadmin>
dir
more info.txt
```
!shot The batch file's output in Command Prompt.
!shot The contents of info.txt.
Close Command Prompt and Notepad.
## Task 2: A PowerShell script <<2>>
@@ Win10
### Open PowerShell ISE as administrator
Search for `PowerShell ISE`, right-click it > **Run as administrator**, and accept UAC. Move to your home folder:
```PS C:\WINDOWS\system32>
cd c:\users\sysadmin
```
The prompt changes to `PS C:\users\sysadmin>`.
### Write the script
Choose **File > New** and enter this in the **Untitled.ps1** script pane:
```file win10info.ps1
Write-Output "Computer name is:"
Get-Content env:computername
Write-Output "Windows version is:"
(Get-WmiObject -Class Win32_OperatingSystem).Caption
Write-Output "CPU is:"
Get-WmiObject Win32_Processor | findstr "Name"
Write-Output "Total Memory is:"
[Math]::Round((Get-WmiObject -Class Win32_ComputerSystem -ComputerName localhost).TotalPhysicalMemory/1Gb)
Write-Output "The Disks that are installed and their freespace:"
Get-WmiObject -Class Win32_LogicalDisk -Filter "DriveType = '3'"
Write-Output "IPv4 addresses:"
Get-NetIPAddress -AddressFamily IPv4 | Sort-Object -Property InterfaceIndex | Format-Table
```
Save it as `C:\Users\sysadmin\win10info.ps1`.
### Try to run it
```PS C:\users\sysadmin>
.\win10info.ps1
```
It fails with **running scripts is disabled on this system**. That's the execution policy doing its job.
!shot The execution policy error.
### Allow local scripts, then run it again
```PS C:\users\sysadmin>
Set-ExecutionPolicy RemoteSigned
```
Click **Yes to All** in the Execution Policy Change window. Then run the script again:
```PS C:\users\sysadmin>
.\win10info.ps1
```
The script now runs.
!tip Which prompt? | The PDF shows these commands at `PS C:\WINDOWS\system32>`, but its own screenshots show `PS C:\users\sysadmin>`, because you ran `cd` first. `.\win10info.ps1` only works from the folder the script is in.
!shot The win10info.ps1 output.
!tip What RemoteSigned means | Scripts you write on this PC run; scripts downloaded from the internet must be signed by a trusted publisher. It's the usual choice for admins. On a real PC, `Set-ExecutionPolicy RemoteSigned -Scope CurrentUser` changes it only for you.
### Compare the two scripts
| Batch | PowerShell |
| `ECHO text` | `Write-Output "text"` |
| `%COMPUTERNAME%` | `$env:computername` (or `Get-Content env:computername`) |
| `systeminfo` piped to `findstr` | `Get-WmiObject` / `Get-CimInstance` returning objects with named properties |
| `>> info.txt` | `Out-File info.txt -Append` (or `>>`) |
## Task 3: A Bash script <<3>>
@@ Lubuntu
### Open nano
Open the **Lubuntu** console and sign in as `sysadmin` with `Train1ng$`. Open **Menu > System Tools > LXTerminal** and start the nano editor:
```sysadmin@lubuntu:~$
nano
```
### Write the script
Type these lines into nano (not at the prompt):
```file lhostinfo.sh
#!/bin/bash
echo "Computer name is: " $HOSTNAME
echo "Operating System and distribution:"
lsb_release -a
echo "CPU cores"
cat /proc/cpuinfo | grep processor
echo "All available memory"
cat /proc/meminfo | grep "MemTotal"
echo "All disk space available."
df -h
echo "All IP addresses"
ip addr show
echo "Show the hostname IP address."
hostname -i
```
!tip The first line matters | `#!/bin/bash` (the **shebang**) tells Linux which interpreter runs the file.
### Save it
Press [[Ctrl]]+[[O]], type `lhostinfo.sh`, and press [[Enter]]. Press [[Ctrl]]+[[X]] to leave nano (or keep it open and use a second terminal).
### Make it executable and run it

Open a second terminal (**Menu > System Tools > LXTerminal**) and run:
```sysadmin@lubuntu:~$
chmod 755 lhostinfo.sh
ls -l lhostinfo.sh
./lhostinfo.sh
```
(`ls -l` is an extra check, not in the PDF.)
`ls -l` now shows `-rwxr-xr-x`: the `x` is execute permission. `./` tells Bash the script is in the current folder, which isn't in the search path.
!shot The `ls -l` line showing execute permission, and the script's output.
The lab is complete.

== reference | Reference: scripting
### Script types on the exam
| Extension | Language | Runs on |
| `.bat`, `.cmd` | Windows batch | Windows Command Prompt |
| `.ps1` | PowerShell | Windows (and PowerShell 7 on macOS and Linux) |
| `.vbs` | VBScript | Windows Script Host (deprecated) |
| `.sh` | Bash / shell script | Linux, macOS, WSL |
| `.js` | JavaScript | Browsers, Node.js, Windows Script Host |
| `.py` | Python | Any OS with Python installed |
### The building blocks (all languages)
| Concept | Batch | PowerShell | Bash |
| Variable | `set NAME=value`, `%NAME%` | `$name = "value"` | `name=value`, `$name` |
| Comment | `rem` or `::` | `#` | `#` |
| Print | `echo` | `Write-Output` | `echo` |
| Condition | `if exist file (...)` | `if ($x -gt 5) { }` | `if [ -f file ]; then ... fi` |
| Loop | `for %%f in (*.txt) do ...` | `foreach ($f in $list) { }` | `for f in *.txt; do ...; done` |
| Pause | `pause` | `Read-Host` | `read` |
### PowerShell execution policies
| Policy | Allows |
| Restricted | No scripts (default on Windows client editions) |
| AllSigned | Only scripts signed by a trusted publisher |
| RemoteSigned | Local scripts; downloaded scripts must be signed |
| Unrestricted | All scripts, with a warning for downloaded ones |
| Bypass | Everything, no warnings (for automation tools) |
```
Get-ExecutionPolicy -List
Set-ExecutionPolicy RemoteSigned -Scope CurrentUser
%% Run one script without changing the policy
powershell -ExecutionPolicy Bypass -File .\script.ps1
```
### Linux permissions
| `chmod` value | Means |
| `755` | Owner: read, write, execute; group and others: read, execute |
| `700` | Owner only, full access |
| `644` | Owner read/write; others read (normal for data files) |
| `+x` | Add execute (`chmod +x script.sh`) |
### Common uses for scripts
| Task | Example |
| Basic automation | Restart a service, clear temp files, gather inventory |
| Map drives at sign-in | `net use S: \\server\share` in a login script |
| Install applications | `winget install` or `msiexec /i app.msi /qn` in a loop |
| Automated backups | `robocopy` on a schedule |
| Gather information | This lab's reports, run on every PC |
| Initiate updates | `winget upgrade --all`, `sudo apt upgrade -y` |
### Scripting risks
- A script runs with your rights; a mistake as admin can delete or misconfigure a lot, fast.
- Downloaded scripts can be malicious; read before you run, and keep execution policy on.
- Avoid storing passwords in plain text inside scripts.
- Scripts can exhaust resources (an infinite loop) or crash a system if untested; test in a VM first (Lab 16).

== stuck | Where people get stuck
| Problem | Why it happens | Fix |
| `Sysinfo.bat` isn't recognized | Saved as `Sysinfo.bat.txt` | Save as type: All Files; rename with `ren` |
| `wmic` is not recognized | WMIC is removed from newer Windows | Use `powershell -c "Get-CimInstance Win32_Processor \| Select Name"` |
| "running scripts is disabled" | Execution policy is Restricted | `Set-ExecutionPolicy RemoteSigned` from an elevated prompt |
| `.\win10info.ps1` not found | You're still in `C:\WINDOWS\system32` | `cd C:\Users\sysadmin` first |
| The Total Memory line errors | It was split across two lines | Keep it on one line |
| `lsb_release: invalid option` | En dash from the PDF | Type `-a` with a hyphen |
| `Permission denied` running the Bash script | No execute permission | `chmod 755 lhostinfo.sh` |
| `lhostinfo.sh: command not found` | Bash doesn't search the current folder | Run it as `./lhostinfo.sh` |

== on-the-job | On the job
| Request | Script approach |
| "Collect the specs of all 40 PCs." | A PowerShell inventory script that writes CSV, run remotely or at sign-in |
| "Everyone needs the S: drive mapped." | A login script or Group Policy drive mapping |
| "Clean temp files on lab PCs nightly." | A batch or PowerShell script in Task Scheduler |
| "Install the same apps on every new laptop." | A winget script |
| "Check disk space on the Linux servers." | A Bash script with `df -h`, run by `cron` |
!tip Professional habit | Put a comment at the top of every script saying what it does, who wrote it, and when. Six months later, that person will be you.

== exam | On the A+ exams
**Core 2 (220-1202)** covers script file types (`.bat`, `.ps1`, `.vbs`, `.sh`, `.js`, `.py`), use cases (basic automation, restarting machines, remapping drives, installing applications, automated backups, gathering information, initiating updates), and risks (introducing malware, inadvertent system changes, browser or system crashes from mishandled resources).
### High-yield facts
- `.bat` = batch, `.ps1` = PowerShell, `.vbs` = VBScript, `.sh` = shell, `.js` = JavaScript, `.py` = Python.
- PowerShell's default execution policy on Windows clients blocks scripts; RemoteSigned is the usual admin setting.
- Linux scripts need execute permission (`chmod +x` or `755`) and a shebang line.
- `>` overwrites a file; `>>` appends.
- Test scripts in a VM or on one PC before running them everywhere.
- Never run a downloaded script you haven't read.

=> A mistake can make widespread, hard-to-undo system changes; and a malicious or tampered script gets full control of the system.
