== overview | Why this lab matters
<p>Every PC runs code before the operating system starts. That code is the <strong>firmware</strong>: the older <strong>BIOS</strong> or the newer <strong>UEFI</strong>. It tests the hardware at power-on (the POST), decides which drive to boot from, and holds settings such as boot passwords, Secure Boot, and the TPM. When a PC won't boot from a USB stick, won't accept a Windows 11 upgrade, or keeps forgetting the date, the fix is often in firmware setup.</p> <p>Once Windows is running, <strong>Device Manager</strong> is the technician's first stop for hardware. It shows every device Windows knows about, flags the ones with problems, and lets you update, roll back, disable, or uninstall the driver that runs each one.</p> <p>By the end you should be able to get into firmware setup two different ways, change the boot order safely, and read a device's driver, events, and resources in Device Manager.</p>

== walkthrough | Walkthrough
## Task 1: Examine the BIOS configuration <<1.1, steps 1–7>>
@@ Win7
### Restart Win7 into BIOS setup
Open the **Win7** console. On the login screen (don't sign in), click the **up arrow** next to the **Shut down** button and choose **Restart**. As soon as the screen goes dark, press [[F2]] repeatedly until the **PhoenixBIOS Setup Utility** opens. If Windows starts loading instead, restart and try again.
!stuck Where people get stuck | The VM console has to have keyboard focus, or your [[F2]] presses go nowhere. Click inside the console window *before* you click Restart.
### Tour the menus
There's no mouse in this utility. Use the arrow keys to move between the tabs along the top, [[Enter]] to select, and the key guide at the bottom for everything else. Review what each tab can view and change:
| Tab | What it controls |
| Main | Basic system configuration, such as the system clock |
| Advanced | Printer port addresses, interrupts, I/O device configuration |
| Security | User and administrator passwords, hard disk boot-sector protection |
| Boot | The boot sequence |
| Exit | Exit the utility with various save or discard options |
Look, but don't change anything except the boot order. A wrong firmware setting can stop the machine from booting.
### Change the boot order
Select the **Boot** tab. Highlight **Removable Devices** and press [[-]] to move it down one level so **Hard Drive** is listed first. In this utility [[+]] moves an item up and [[-]] moves it down.
!shot The Boot tab with Hard Drive at the top of the list.
!tip Why a tech does this | Putting the internal drive first stops the PC from trying to boot from a USB stick someone left plugged in. When you *need* to boot from USB, most PCs have a one-time boot menu (often [[F12]]) so you don't have to change the order.
### Save and exit
Go to the **Exit** tab, highlight **Exit Saving Changes**, press [[Enter]], select **Yes**, and press [[Enter]] again. Win7 restarts with the new order.

## Task 2: Reach UEFI settings from Windows 10 <<1.2, steps 1–11>>
@@ Win10
### Sign in to Win10
Open the **Win10** console, click anywhere on the splash screen, and sign in as `sysadmin` with `Train1ng$`.
### Restart into Advanced startup
Click **Start > Settings > Update & Security > Recovery**. Under **Advanced startup**, click **Restart now**.
### Find the Advanced options
When the blue **Choose an option** screen appears, click **Troubleshoot > Advanced options**. View the tiles. On a UEFI PC a **UEFI Firmware Settings** tile would be here; it restarts straight into firmware setup. This VM uses legacy BIOS, so the tile is missing. That is expected. Click the **back arrow**.
!shot The Advanced options screen showing the tiles that are available.
### Back out and boot normally
Click the **back arrow** on the **Troubleshoot** page, then click **Continue** on **Choose an option** to start Windows normally.
!tip Optional extra, not a lab step | On a real UEFI PC you can reach the same screens from an elevated Command Prompt. Don't run these in the lab; they restart the VM. // `shutdown /r /o /t 0` restarts into Advanced startup. `shutdown /r /fw /t 0` restarts straight into UEFI firmware setup (UEFI PCs only). Holding [[Shift]] while you click **Restart** also opens Advanced startup.

## Task 3: Device Manager from Control Panel <<2.1, steps 1–11>>
@@ Win7
### Open Device Manager
Sign in to **Win7** as `sysadmin` with `Train1ng$`. Click **Start > Control Panel**, change **View by** to **Small icons**, and click **Device Manager**.
### Show hidden devices
Click **View** on the menu bar to see the other views (the default is **Devices by type**), then select **Show hidden devices**. That adds non-Plug and Play drivers, low-level system drivers, and drivers installed by third-party software.
### Read the hardware
Click the arrow next to **Processors** to see the CPU model and speed, then the arrow next to **Mice and other pointing devices**.
!shot Device Manager with hidden devices shown and Processors expanded.
### Inspect the driver, and don't roll it back
Right-click **VMware Pointing Device** and click **Properties**. Windows 7 shows four tabs: General, Driver, Details, and Resources. On the **Driver** tab, review the buttons, then click **Roll Back Driver**, read the prompt, and click **No**.
!shot The Driver tab or the Roll Back confirmation prompt.
### Check the resources
Click the **Resources** tab. It lists the resources the device uses (here an IRQ) and a **Conflicting device list** at the bottom. Don't change these settings. Click **OK** and close the remaining windows.
!now For comparison | On Windows 8.1 and 10, the PDF notes you can also right-click **Start > Control Panel > Device Manager**. Later Windows 10 builds and Windows 11 replaced Control Panel on that menu with Settings, so use **Device Manager** from the same right-click menu instead.

## Task 4: Device Manager through Run <<2.2, steps 1–11>>
@@ Win10
### Open Run
Switch to **Win10** and sign in if needed. Right-click **Start** to open the Power User menu and click **Run**.
### Launch Device Manager
In the Run box, type the command below and click **OK**.
```Run box:
devmgmt.msc
```
### Open the display adapter
Expand **Display adapters**, right-click the adapter (**VMware SVGA 3D**), and click **Properties**. Windows 10 shows five tabs: General, Driver, Details, **Events**, and Resources.
### Read the device's history
Click the **Events** tab. It lists when the device was installed, started, configured, or updated. Click **View All Events** to open Event Viewer, then click the **Details** tab in the main pane and review it. Close Event Viewer.
!shot The Events tab or the Event Viewer details for the display adapter.
### Finish
Click **OK** to close the Properties window. The lab is complete.

== reference | Reference: firmware and Device Manager
<h3>BIOS compared with UEFI</h3> <div class="tbl"><table> <thead><tr><th scope="col"></th><th scope="col">Legacy BIOS</th><th scope="col">UEFI</th></tr></thead> <tbody> <tr><th scope="row">Interface</th><td>Text menus, keyboard only</td><td>Often graphical, with mouse support</td></tr> <tr><th scope="row">Boot disk format</th><td>MBR: disks up to about 2 TB, four primary partitions</td><td>GPT: very large disks, up to 128 partitions in Windows</td></tr> <tr><th scope="row">Security</th><td>Setup and boot passwords</td><td>Adds Secure Boot, which blocks unsigned boot loaders</td></tr> <tr><th scope="row">Windows 11</th><td>Not supported</td><td>Required, with Secure Boot capability and TPM 2.0</td></tr> <tr><th scope="row">Older OS support</th><td>Native</td><td>Through CSM (Compatibility Support Module) if the board offers it</td></tr> </tbody></table></div> <h3>Firmware settings you'll be asked about</h3> <ul> <li><strong>Boot options:</strong> boot order, one-time boot menu, USB and network (PXE) boot.</li> <li><strong>Passwords:</strong> a supervisor (administrator) password protects setup; a user or power-on password is needed to boot at all.</li> <li><strong>Secure Boot and TPM:</strong> both needed for Windows 11, and the TPM is used by BitLocker (Lab 15).</li> <li><strong>Virtualization:</strong> Intel VT-x or AMD-V must be on for Hyper-V (Lab 16).</li> <li><strong>Hardware monitoring:</strong> CPU temperature, fan speeds, and voltages.</li> <li><strong>USB permissions:</strong> enable or disable ports, often for security.</li> </ul> <h3>Getting into setup</h3> <p>The key depends on the board maker, not Windows. Watch the boot screen or check the manual. Common setup keys are <kbd>Del</kbd>, <kbd>F2</kbd>, <kbd>F10</kbd>, <kbd>F1</kbd>, and <kbd>Esc</kbd>. One-time boot menus are often <kbd>F12</kbd>, <kbd>F11</kbd>, <kbd>F9</kbd>, or <kbd>F8</kbd>.</p> <h3>Ways to open Device Manager</h3> <div class="tbl"><table> <thead><tr><th scope="col">Method</th><th scope="col">How</th></tr></thead> <tbody> <tr><td>Run or a command prompt</td><td><code>devmgmt.msc</code></td></tr> <tr><td>Power User menu</td><td><kbd>Win</kbd>+<kbd>X</kbd> &gt; Device Manager</td></tr> <tr><td>Computer Management</td><td><code>compmgmt.msc</code> &gt; System Tools &gt; Device Manager</td></tr> <tr><td>Control Panel</td><td>Small icons view &gt; Device Manager</td></tr> </tbody></table></div> <h3>Reading the device list</h3> <div class="tbl"><table> <thead><tr><th scope="col">You see</th><th scope="col">It means</th></tr></thead> <tbody> <tr><td>Yellow triangle with "!"</td><td>The device has a problem. Open Properties &gt; General to read the error code.</td></tr> <tr><td>Down arrow on the icon</td><td>The device is disabled.</td></tr> <tr><td>"Unknown device" or "Other devices"</td><td>Windows has no driver for it.</td></tr> <tr><td>Faded (grey) icon</td><td>A hidden device, or one that isn't currently connected.</td></tr> </tbody></table></div> <h3>Error codes worth knowing</h3> <div class="tbl"><table> <thead><tr><th scope="col">Code</th><th scope="col">Meaning</th><th scope="col">First thing to try</th></tr></thead> <tbody> <tr><td>Code 10</td><td>This device cannot start</td><td>Update or reinstall the driver</td></tr> <tr><td>Code 22</td><td>The device is disabled</td><td>Right-click &gt; Enable device</td></tr> <tr><td>Code 28</td><td>Drivers aren't installed</td><td>Install the maker's driver</td></tr> <tr><td>Code 43</td><td>Windows stopped the device because it reported problems</td><td>Reseat or replace the hardware, then reinstall the driver</td></tr> </tbody></table></div> <h3>Driver tab buttons</h3> <div class="tbl"><table> <thead><tr><th scope="col">Button</th><th scope="col">Use it when</th></tr></thead> <tbody> <tr><td>Driver Details</td><td>You need the driver file names and versions</td></tr> <tr><td>Update Driver</td><td>A newer driver should fix a bug or add support</td></tr> <tr><td>Roll Back Driver</td><td>A device broke right after a driver update. Greyed out if there's no earlier driver saved.</td></tr> <tr><td>Disable Device</td><td>You want the device off without removing its driver</td></tr> <tr><td>Uninstall Device</td><td>You want a clean reinstall. Use Action &gt; Scan for hardware changes to detect it again.</td></tr> </tbody></table></div>

== exam | On the A+ exams
<p><strong>Core 1 (220-1201)</strong> expects you to configure BIOS/UEFI settings and to recognize firmware-related symptoms. <strong>Core 2 (220-1202)</strong> lists Device Manager among the Windows tools you should know by name and by its <code class="inl">.msc</code> shortcut.</p> <h3>High-yield facts</h3> <ul> <li>The setup key comes from the board maker, not the operating system.</li> <li>UEFI pairs with GPT disks; legacy BIOS pairs with MBR. Windows 11 requires UEFI, Secure Boot capability, and TPM 2.0.</li> <li>Supervisor password protects setup; user or power-on password protects booting.</li> <li>Wrong time and lost settings after power-off point to a dead CMOS battery.</li> <li><code class="inl">devmgmt.msc</code> opens Device Manager. A yellow "!" means a problem; a down arrow means disabled.</li> <li>Roll Back Driver is the first fix when a device fails right after a driver update.</li> </ul>

== check | Check yourself
<div class="q"><p class="ask">1. A user's PC keeps trying to boot from a USB drive left in the port. What setting do you change, and where?</p> <button type="button" class="btn reveal" aria-expanded="false">Show answer</button> <div class="ans">The boot order, in BIOS/UEFI setup. Put the internal drive first. For the rare times you need USB boot, use the one-time boot menu instead.</div></div> <div class="q"><p class="ask">2. You're upgrading a PC to Windows 11 and the check fails on Secure Boot. The disk is MBR. What has to change?</p> <button type="button" class="btn reveal" aria-expanded="false">Show answer</button> <div class="ans">Secure Boot needs UEFI boot mode, and UEFI boots from GPT disks. Convert the disk to GPT (Windows includes the <code class="inl">mbr2gpt</code> tool), switch firmware to UEFI, then enable Secure Boot.</div></div> <div class="q"><p class="ask">3. A network adapter stopped working right after a driver update. What's the fastest fix in Device Manager?</p> <button type="button" class="btn reveal" aria-expanded="false">Show answer</button> <div class="ans">Properties &gt; Driver &gt; Roll Back Driver, which restores the previous driver version.</div></div> <div class="q"><p class="ask">4. Why might the UEFI Firmware Settings tile be missing from Advanced options?</p> <button type="button" class="btn reveal" aria-expanded="false">Show answer</button> <div class="ans">The PC is running in legacy BIOS mode (or Windows was installed in legacy mode). The tile appears only on UEFI installations.</div></div> <div class="q"><p class="ask">5. What does Show hidden devices add to the Device Manager list?</p> <button type="button" class="btn reveal" aria-expanded="false">Show answer</button> <div class="ans">Non-Plug and Play drivers, low-level system drivers, drivers installed by other software, and devices that were installed but aren't connected now.</div></div>
