== overview | Why this lab matters
Remote access lets you see and control a PC from anywhere on the network: fix a setting, check Task Manager, gather information, or show a user how to do something. It also opens a door that attackers look for, so every remote tool has to be set up deliberately.
**Remote Desktop (RDP)** is built into Windows. On the host it needs three things: the feature turned on, the user allowed to connect, and the firewall allowing it. **VNC** is a cross-platform alternative that shares the actual screen the user sees, which is useful when you want to watch what they're doing rather than start a separate session.
You'll configure both, connect each way, and use Task Manager over the remote session to collect performance information the way you would for a "my PC is slow" call.

== walkthrough | Walkthrough
## Task 1: Enable Remote Desktop on Win7 <<1.1>>
@@ Win7
### Turn it on
Open the **Win7** console and sign in as `sysadmin` with `Train1ng$`. Click **Start**, right-click **Computer**, and choose **Properties**. Click **Remote settings** in the left pane. On the **Remote** tab, select **Allow connections from computers running any version of Remote Desktop (less secure)** and click **Apply**.
!tip Why "less secure"? | The other option requires Network Level Authentication, which older clients don't support. The lab uses the broad setting for compatibility. On real PCs, choose NLA.
### Check who may connect
Click **Select Users**. sysadmin already has access because administrators are allowed by default. Click **OK**, then **OK** again in System Properties.
!shot The Win7 Remote tab with Remote Desktop allowed.
### Allow it through the firewall
In the System window, click **Control Panel Home**, set **View by** to **Small icons**, and click **Windows Firewall**. Click **Allow a program or feature through Windows Firewall**, then **Change settings**. Make sure **Remote Desktop** is checked, and its **Home/Work (Private)** column too. Click **OK** and close Windows Firewall.
### Log off Win7
Click **Start**, the arrow next to **Shut down**, and **Log off**. (An RDP session can't share the console with a signed-in user on Windows 7.)
## Task 2: Enable Remote Desktop on Win10 <<1.2>>
@@ Win10
### Turn it on in Settings
Open the **Win10** console, click the splash screen, and sign in as `sysadmin` with `Train1ng$`. Right-click **Start > Settings > System > Remote Desktop**. Click the **Off** switch under **Enable Remote Desktop** and click **Confirm**. Under **User accounts**, click **Select users that can remotely access this PC**, confirm sysadmin has access (add it if needed), and click **OK**.
### Check the firewall rule
In the **Find a setting** box, start typing `Windows Firewall` and click **Allow an app through Windows Firewall**. Click **Change settings** and make sure **Remote Desktop** is checked, and its **Private** column too. Click **OK**. Leave Win10 open.
!shot The Win10 firewall allowed-apps list with Remote Desktop checked for Private.
## Task 3: Connect from Win10 to Win7 <<1.3>>
@@ Win10
### Open Remote Desktop Connection
On **Win10**, click the search button, start typing `Remote Desktop Connection`, and open it. Click **Show Options** and enter:
```Computer:
192.168.1.7
```
```User name:
sysadmin
```
Click **Connect**. When asked for credentials, enter `Train1ng$` and click **OK**. Click **Yes** at the certificate warning.
!stuck Certificate warning | RDP uses a self-signed certificate on each PC, so the client can't verify it. In a lab that's expected. On a real network, a warning you don't expect can mean you're connecting to the wrong machine.
### Work on the remote desktop
{{on Win7}} You're still at the Win10 console, but everything inside the RDP window happens on Win7; the connection bar at the top says so. Right-click the desktop, choose **New > Text Document**, name it `remote access`, and press [[Enter]]. Open it, type `This file was created remotely from Win10.`, click **File > Save**, and close Notepad.
!shot The RDP session to Win7 showing the connection bar and the remote access file.
### Disconnect
Click the **X** on the connection bar and click **OK**.
## Task 4: Connect from Win7 to Win10 <<1.4>>
@@ Win7
### Confirm the file at the Win7 console
Go to the **Win7** console directly (not through Win10) and sign in as `sysadmin`. Open **remote access** on the desktop, add a new line `Confirmed by Win7 client.`, click **File > Save**, and close Notepad.
### Open a session to Win10
Click **Start**, type `Remote Desktop` in the search field, and open **Remote Desktop Connection**. Enter the Win10 address and click **Connect**:
```Computer:
192.168.1.10
```
Enter user name `sysadmin` and password `Train1ng$`, click **OK**, and click **Yes** at the certificate prompt. If the session doesn't start right away, wait 2–3 minutes. The connection bar shows the Win10 address.
## Task 5: Troubleshoot over RDP <<1.5>>
@@ Win7
### Capture performance data
{{on Win10}} You're at the Win7 console, working inside the RDP window on Win10. Right-click the taskbar and choose **Task Manager**, make sure you're in **More details**, and click **Performance**. Right-click the **CPU** graph and choose **Copy**.
### Save it to a file
{{on Win10}} Still in the session, right-click the desktop, choose **New > Text Document**, and name it `remote session.txt`. Open it, right-click, choose **Paste**, and click **File > Save**. Close the file and Task Manager.
!shot The remote session.txt file showing the pasted CPU summary.
### Disconnect properly
{{on Win10}} Click **Start > Power > Disconnect**. You're back on the Win7 console; leave it open.
!tip Disconnect or sign out? | **Disconnect** leaves your programs running on the remote PC so you can reconnect. **Sign out** closes them. Signing out is cleaner when you're done.
## Task 6: TightVNC <<2.1–2.3>>
@@ Win7
### Install the server on Win7
On **Win7**, open **Installs** on the desktop and double-click this package. Click **Run** at the security warning.
```File to run:

```
Click **Next**, accept the license, **Next**, choose **Typical**, keep every box checked (file associations, server options, firewall exceptions), **Next**, then **Install**. Click **Yes** at UAC.
### Set the passwords
In **TightVNC Server: Set Passwords**, select **Require password-based authentication** and enter `VNCpwd` in both fields. Select **Protect control interface with an administrative password** and enter `VNCpwd` in both fields. Click **OK**, then **Finish**.
!shot The TightVNC Set Passwords window with both options selected.
### Check the service settings
The service is already running and starts at boot. Open **Start > All Programs > TightVNC > TightVNC Server (Service Mode) > TightVNC Service - Offline Configuration** and click **Yes** at UAC. If the window doesn't appear, click its taskbar icon. On the **Server** tab, under **Miscellaneous**, make sure **Hide desktop wallpaper** and **Show icon in the notification area** are unchecked. Click **OK**.

### Install only the viewer on Win10
Change focus to **Win10** (sign in as `sysadmin` if needed). Open **Toolbox** on the desktop and double-click this package; click **Run** if warned.

== reference | Reference: remote access tools
### Compare the options
| Tool | Port | What you see | Best for |
| Remote Desktop (RDP) | TCP 3389 | A separate session; the local user is signed out | Admin work on Windows PCs and servers |
| VNC | TCP 5900 | The real console screen | Watching or helping a user on any OS |
| Quick Assist | Over the internet (HTTPS) | The user's screen, after they enter a code | Helping a home or remote user with no setup |
| Remote Assistance (`msra`) | Varies | The user's screen, by invitation | Legacy Windows help |
| SSH | TCP 22 | A command line | Linux, network devices, Windows OpenSSH |
| RMM tools | Vendor cloud | Agent-based control and monitoring | Managed service providers |
| VPN | Varies | Puts you on the remote network | Reaching internal resources securely before RDP |
### mstsc options
```
mstsc /v:192.168.1.7
mstsc /v:server01 /f
mstsc /v:server01 /admin
```
`/v` sets the computer, `/f` opens full screen, and `/admin` connects to the server's administrative session.
### Remote Desktop Connection tabs (Show Options)
| Tab | Sets |
| General | Computer, user name, save the connection as an `.rdp` file |
| Display | Size and color depth, multiple monitors |
| Local Resources | Clipboard, printers, drives, and audio passed to the remote PC |
| Experience | Visual quality vs. speed |
| Advanced | Server authentication behavior, RD Gateway |
### Securing remote access
- Require **NLA** and strong passwords; use MFA where the tool supports it.
- Allow only the users who need it (the Remote Desktop Users group).
- Don't expose port 3389 or 5900 to the internet. Use a VPN or a gateway.
- Keep firewall rules to the **Private** or **Domain** profile, not Public.
- Get the user's permission before taking control of their screen, and tell them when you're done.
- Remove or disable tools like VNC when they're no longer needed.

== stuck | Where people get stuck
| Problem | Why it happens | Fix |
| "Remote Desktop can't connect to the remote computer" | Feature off, firewall blocking 3389, or the PC is asleep | Check the Remote tab, firewall rule, and that the host is on |
| Credentials rejected | Wrong user format or the account isn't allowed | Use `sysadmin` (or `COMPUTER\sysadmin`); check Select Users |
| Win10 session takes minutes to start | First connection builds the session | Wait 2–3 minutes |
| No Remote Desktop option in Settings | Windows Home edition | Use Quick Assist or upgrade to Pro |
| TightVNC Viewer can't connect | Server service isn't running or the firewall exception wasn't added | Restart the TightVNC service on Win7; rerun setup with the firewall box checked |
| VNC password refused | Case-sensitive | `VNCpwd` with capital V, N, C |

== on-the-job | On the job
| The ticket says | Tool | Approach |
| "My PC is slow." (remote user) | Quick Assist or RMM | Ask permission, watch Task Manager, gather data, fix or escalate |
| "Restart the print server tonight." | RDP | Connect, check sessions, restart, confirm services came back |
| "Show me how to do this." | VNC, Quick Assist | Share the user's screen so they can watch |
| "Fix the firewall on the Linux box." | SSH | Command-line access over port 22 |
| "Work from home and use the office file share." | VPN | Connect to the network first, then use resources |
!tip Professional habit | Always tell the user before you connect to their screen and when you disconnect, and note the session in the ticket.

== exam | On the A+ exams
**Core 2 (220-1202)** covers remote access methods and their security considerations: RDP, VPN, VNC, SSH, remote monitoring and management (RMM), Microsoft Remote Assistance, Quick Assist, and third-party screen-sharing tools. **Core 1 (220-1201)** covers port numbers.
### High-yield facts
- RDP uses TCP 3389; SSH TCP 22; VNC TCP 5900.
- Windows Home can't host Remote Desktop.
- NLA authenticates before a session is created; leave it on.
- RDP starts a separate session; VNC and Quick Assist share the user's screen.
- Don't expose RDP directly to the internet; use a VPN or gateway.
- `mstsc` launches Remote Desktop Connection; `msra` launches Remote Assistance.

== check | Check yourself
?? A user on Windows 11 Home asks you to Remote Desktop into their PC. Why won't it work, and what can you use instead?
=> Home edition can't host RDP sessions. Use Quick Assist, a third-party tool, or upgrade to Pro.
?? Which port must the host's firewall allow for Remote Desktop?
=> TCP 3389.
?? You want to watch exactly what a user is doing on screen. RDP or VNC?
=> VNC (or Quick Assist). RDP starts a separate session and signs the local user out.
?? What does Network Level Authentication protect against?
=> It requires the user to authenticate before the remote session is created, so unauthenticated attackers can't reach the sign-in screen or use as many server resources.
?? A manager wants RDP open to the internet so staff can work from home. What do you recommend instead?
=> Have staff connect through a VPN (or RD Gateway) first, with MFA, and keep port 3389 closed to the internet.

== cheat | Cheat sheet
## RDP
- Host: Settings > System > Remote Desktop (Pro+)
- Firewall: allow Remote Desktop (Private)
- Users: admins + Remote Desktop Users
- `mstsc /v:host`; TCP 3389
- Keep NLA on; VPN for outside access
## Other tools
- VNC: TCP 5900, shares the real screen
- Quick Assist: [[Win]]+[[Ctrl]]+[[Q]]
- `msra` Remote Assistance
- SSH: TCP 22
- RMM for managed fleets
