Deploy a Virtual Machine with Hyper-V

A virtual machine is a whole computer running as software inside another one. You will check that Win10's hardware can host VMs, enable Hyper-V from PowerShell, build a VM with memory, a virtual switch, and a virtual disk, and install Lubuntu into it from an ISO.

Why this lab matters

Virtualization is everywhere: the lab machines you're using are VMs, most servers are VMs, and cloud services are built on the same idea. On a workstation, VMs let you test software or updates safely, run an older OS for a legacy app, try a Linux distribution, or open something suspicious in isolation.

Hyper-V is Microsoft's hypervisor. It's built into Pro, Enterprise, and Education editions but has to be turned on, and it needs hardware support: a 64-bit CPU with virtualization extensions and SLAT. You'll confirm the hardware, enable the feature, then make the choices every VM needs: generation, memory, network switch, virtual disk, and install media.

Walkthrough

Task 1: Check the hardware

1Run systeminfo in an elevated PowerShell

Log in to Win10. Search for PowerShell, right-click Windows PowerShell > Run as administrator, and accept UAC. Run:

systeminfo.exe

Scroll to the bottom. Hyper-V Requirements either lists four "Yes" items (VM Monitor Mode Extensions, virtualization enabled in firmware, SLAT, Data Execution Prevention) or says A hypervisor has been detected, which means one is already running. Either way, this PC can run Hyper-V.

ScreenshotThe Hyper-V Requirements section of systeminfo.

A correction to the PDF

The PDF calls the CPU feature "VT-c." The extensions Hyper-V needs are Intel VT-x or AMD-V, plus SLAT (Intel EPT or AMD RVI), turned on in the firmware (Lab 01-A).

Task 2: Enable Hyper-V

2Enable the feature

In the same PowerShell window, run:

Enable-WindowsOptionalFeature -Online -FeatureName Microsoft-Hyper-V -All

Read the output, press Y and Enter to restart.

Where people get stuck

The PDF splits this command across two lines. Type it as one line, or use the Copy button.

3Confirm it in Windows Features

After signing back in, search for turn windows features on or off and open it. Hyper-V is checked. Click OK.

ScreenshotWindows Features with Hyper-V checked.

Task 3: Create the VM

4Start the wizard

Search for Hyper-V Manager, right-click it > Run as administrator. Choose Action > New > Virtual Machine and click Next.

5Work through the settings

Review the summary and click Finish.

The ISO name in the PDF

The PDF shows the file as ...desktop-amd6.iso. The real name ends in amd64.iso. Browse to ToolBox and pick the Lubuntu ISO you see.

Task 4: Install Lubuntu

6Start the VM and boot the live image

Right-click New-Lubuntu > Connect, then click Start. Choose English, then Try Lubuntu without installation with the arrow keys and Enter.

7Run the installer

On the live desktop, double-click Install Lubuntu 18.04.3 LTS (drag the window to the center if it's cut off). Then:

"Erase disk" is safe here

It erases only the VM's new 10 GB virtual disk, not Win10's drive.

8Restart and sign in

When the install finishes, click Restart Now, and press Enter when asked to remove the install media. Sign in with Train1ng$ and close the Update information window.

VM building blocks

PartChoices
GenerationGen 1: legacy BIOS, IDE boot, older OSs. Gen 2: UEFI, Secure Boot, SCSI boot, faster.

On the job

RequestApproach
"Can I test this update before we roll it out?"Clone a VM of a standard PC, checkpoint it, apply the update, test, roll back
"Our accounting app only runs on an old Windows."Run that OS in a VM, isolated from the internet if it's unsupported
"I need Linux for a class but I have a Windows laptop."Hyper-V or VirtualBox VM, or WSL for command-line work
"Is this attachment safe?"Open it in Windows Sandbox or an isolated VM, never on the user's PC
"VMs are slow on this PC."Check RAM, CPU virtualization settings, and disk; use an SSD and avoid over-allocating memory
Professional habit

Take a checkpoint before every risky change in a VM. It's the fastest undo you'll ever have, but delete old checkpoints so they don't fill the disk.

High-yield facts

  • Type 1 hypervisors run on bare metal; Type 2 run on a host OS.
  • Hyper-V needs a 64-bit Pro/Enterprise/Education edition and VT-x or AMD-V with SLAT enabled in firmware.
  • Virtualization must be turned on in BIOS/UEFI.
  • External switch = real network; Internal = host and VMs; Private = VMs only.
  • Each VM needs its own OS license and its own security updates and antimalware.
  • IaaS, PaaS, SaaS: how much the provider manages.

Check yourself

1. systeminfo says "Virtualization Enabled In Firmware: No." What do you do?

Restart into BIOS/UEFI setup and enable Intel VT-x or AMD-V, then save and restart.

2. A user with Windows 11 Home wants to run a Linux VM. Can they use Hyper-V?

No; Hyper-V isn't in Home. They can use a Type 2 hypervisor such as VirtualBox, or upgrade to Pro.

3. Which virtual switch type lets a VM appear on the physical network like any other PC?

External.

4. Is Hyper-V a Type 1 or Type 2 hypervisor?

Type 1. Once enabled, it runs directly on the hardware and Windows itself runs in a privileged partition above it.

5. Why should a VM have antimalware and updates even though it's "just a VM"?

It's a full OS on the network with the same vulnerabilities as a physical PC, and a compromised VM can attack other systems.
