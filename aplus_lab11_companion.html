Why this lab matters

Remote access lets you see and control a PC from anywhere on the network: fix a setting, check Task Manager, gather information, or show a user how to do something. It also opens a door that attackers look for, so every remote tool has to be set up deliberately.

Remote Desktop (RDP) is built into Windows. On the host it needs three things: the feature turned on, the user allowed to connect, and the firewall allowing it. VNC is a cross-platform alternative that shares the actual screen the user sees, which is useful when you want to watch what they're doing rather than start a separate session.

You'll configure both, connect each way, and use Task Manager over the remote session to collect performance information the way you would for a "my PC is slow" call.

Walkthrough

Task 1: Enable Remote Desktop on Win7

1Turn it on

Log in to Win7. Click Start, right-click Computer > Properties > Remote settings. On the Remote tab, select Allow connections from computers running any version of Remote Desktop (less secure) and click Apply.

Why "less secure"?

The other option requires Network Level Authentication, which older clients don't support. The lab uses the broad setting for compatibility. On real PCs, choose NLA.

2Check who may connect

Click Select Users. sysadmin already has access because administrators are allowed by default. Click OK twice.

ScreenshotThe Win7 Remote tab with Remote Desktop allowed.

3Allow it through the firewall

Open Control Panel > Windows Firewall > Allow a program or feature through Windows Firewall > Change settings. Check Remote Desktop and its Home/Work (Private) column. Click OK. Log off Win7.

Task 2: Enable Remote Desktop on Win10

4Turn it on in Settings

Log in to Win10. Right-click Start > Settings > System > Remote Desktop, switch Enable Remote Desktop on, and click Confirm. Click Select users that can remotely access this PC and confirm sysadmin has access.

5Check the firewall rule

In the Settings search box, type firewall and open Allow an app through Windows Firewall. Click Change settings and make sure Remote Desktop is checked for Private. Click OK.

ScreenshotThe Win10 firewall allowed-apps list with Remote Desktop checked for Private.

Task 3: Connect from Win10 to Win7

6Open Remote Desktop Connection

On Win10, search for Remote Desktop Connection and open it (or run mstsc). Click Show Options, enter 192.168.1.7 as the computer and sysadmin as the user name, and click Connect. Enter Train1ng$, then click Yes at the certificate warning.

Certificate warning

RDP uses a self-signed certificate on each PC, so the client can't verify it. In a lab that's expected. On a real network, a warning you don't expect can mean you're connecting to the wrong machine.

7Work on the remote desktop

The connection bar at the top shows you're on Win7. Create a text document on the desktop named remote access, open it, type This file was created remotely from Win10., save, and close.

ScreenshotThe RDP session to Win7 showing the connection bar and the remote access file.

8Disconnect

Click the X on the connection bar and click OK.

Task 4: Connect from Win7 to Win10

9Confirm the file at the Win7 console

Go to Win7 directly and sign in. Open remote access, add a line Confirmed by Win7 client., save, and close.

10Open a session to Win10

Search for Remote Desktop Connection, connect to 192.168.1.10 as sysadmin / Train1ng$, and click Yes at the certificate prompt. If it doesn't start right away, wait 2–3 minutes.

Task 5: Troubleshoot over RDP

11Capture performance data

In the Win10 session, right-click the taskbar > Task Manager > More details > Performance. Right-click the CPU graph and choose Copy.

12Save it to a file

Create remote session.txt on the remote desktop, open it, Paste, and save. You now have a snapshot of the remote PC's CPU details to compare later.

ScreenshotThe remote session.txt file showing the pasted CPU summary.

13Disconnect properly

Close Task Manager, then Start > Power > Disconnect.

Disconnect or sign out?

Disconnect leaves your programs running on the remote PC so you can reconnect. Sign out closes them. Signing out is cleaner when you're done.

Task 6: TightVNC

14Install the server on Win7

On Win7, open Installs on the desktop and run tightvnc-2.8.8-gpl-setup-32bit. Accept the license, choose Typical, keep all boxes checked (file associations, service, firewall exception), and install. Accept UAC.

15Set the passwords

Select Require password-based authentication and enter VNCpwd twice. Select Protect control interface with an administrative password and enter VNCpwd twice. Click OK, then Finish.

ScreenshotThe TightVNC Set Passwords window with both options selected.

16Check the service settings

Open Start > All Programs > TightVNC > TightVNC Server (Service Mode) > TightVNC Service - Offline Configuration and accept UAC. On the Server tab, under Miscellaneous, uncheck Hide desktop wallpaper and Show icon in the notification area. Click OK.

17Install only the viewer on Win10

On Win10, open Toolbox and run tightvnc-2.8.8-gpl-setup-64bit. Choose Custom, set TightVNC Server to Entire feature will be unavailable, and finish the install.

18Connect with VNC

Search for and open TightVNC Viewer. Enter 192.168.1.7 as the Remote Host, click Connect, and enter VNCpwd. You're now viewing and controlling Win7's actual console.

ScreenshotTightVNC Viewer on Win10 showing the Win7 desktop.

The lab is complete.

Securing remote access

  • Require NLA and strong passwords; use MFA where the tool supports it.
  • Allow only the users who need it (the Remote Desktop Users group).
  • Don't expose port 3389 or 5900 to the internet. Use a VPN or a gateway.
  • Keep firewall rules to the Private or Domain profile, not Public.
  • Get the user's permission before taking control of their screen, and tell them when you're done.
  • Remove or disable tools like VNC when they're no longer needed.

High-yield facts

  • RDP uses TCP 3389; SSH TCP 22; VNC TCP 5900.
  • Windows Home can't host Remote Desktop.
  • NLA authenticates before a session is created; leave it on.
  • RDP starts a separate session; VNC and Quick Assist share the user's screen.
  • Don't expose RDP directly to the internet; use a VPN or gateway.
  • mstsc launches Remote Desktop Connection; msra launches Remote Assistance.

Check yourself

1. A user on Windows 11 Home asks you to Remote Desktop into their PC. Why won't it work, and what can you use instead?

Home edition can't host RDP sessions. Use Quick Assist, a third-party tool, or upgrade to Pro.

2. Which port must the host's firewall allow for Remote Desktop?

TCP 3389.

3. You want to watch exactly what a user is doing on screen. RDP or VNC?

VNC (or Quick Assist). RDP starts a separate session and signs the local user out.

4. What does Network Level Authentication protect against?

It requires the user to authenticate before the remote session is created, so unauthenticated attackers can't reach the sign-in screen or use as many server resources.

5. A manager wants RDP open to the internet so staff can work from home. What do you recommend instead?

Have staff connect through a VPN (or RD Gateway) first, with MFA, and keep port 3389 closed to the internet.

Cheat sheet

RDP

  • Host: Settings > System > Remote Desktop (Pro+)
  • Firewall: allow Remote Desktop (Private)
  • Users: admins + Remote Desktop Users
  • mstsc /v:host; TCP 3389
  • Keep NLA on; VPN for outside access

Other tools

  • VNC: TCP 5900, shares the real screen
  • Quick Assist: Win+Ctrl+Q
  • msra Remote Assistance
  • SSH: TCP 22
  • RMM for managed fleets
