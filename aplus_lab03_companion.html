Why this lab matters

Before you blame the network, check the PC. Is the adapter enabled? Does it have a valid IP address, subnet mask, gateway, and DNS server? Can it reach its neighbor? Its gateway? A name?

This lab gives you both halves of that check. The graphical side is Network and Sharing Center, adapter properties, sharing profiles, and the troubleshooters. The command-line side is ipconfig, ping, tracert, netstat, net, and nslookup. The command line is faster, works over a remote session, and gives you output you can paste into a ticket.

Walkthrough

Task 1: Network and Sharing Center (Win7)

1Open Network and Sharing Center

Log in to Win7. Open Start > Control Panel, set View by to Small icons, and click Network and Sharing Center. Read the options: set up a new connection or network, connect to a network, sharing options, and troubleshoot problems. Click Connect to a network; only an Unidentified network shows here.

2Set a static IP address

Click Change adapter settings, right-click Local Area Connection, and choose Properties. Double-click Internet Protocol Version 4 (TCP/IPv4) and change the IP address to 192.168.1.77. Leave the subnet mask as 255.255.255.0. Click OK twice.

ScreenshotThe IPv4 Properties window showing 192.168.1.77.

3Confirm it from the command line

Open Start, type cmd, and open it. Run:

ipconfig /all

Check that the IPv4 address reads 192.168.1.77. Type exit, then go back to Network and Sharing Center.

Task 2: Advanced sharing settings (Win7)

4Lock down the current profile

Click Change advanced sharing settings. For the Home or Work profile:

SettingChoose
File and printer sharingTurn off
Media streamingOff, unless you need it (it opens several firewall ports)
File sharing connections128-bit encryption
Password protected sharingTurn on

Read the remaining options, then click Save changes.

ScreenshotThe Advanced sharing settings page with your choices.

Task 3: Troubleshooters

5Run the Network Adapter troubleshooter (Win7)

In Network and Sharing Center, click Troubleshoot problems > Network Adapter > Next. Watch what it checks. It should find nothing wrong. Click Close.

6Run the network troubleshooter (Win10)

Log in to Win10. Open Start > Settings > Network & Internet, and under Status click Troubleshoot. Read what it reports. Because there's no internet here, it will likely report a problem it can't fix. Click Close.

ScreenshotThe Win10 network troubleshooter's results.

Task 4: Network command-line tools (Win10)

7Open an elevated prompt

Click Start, type cmd, right-click Command Prompt, and choose Run as administrator. Accept UAC.

8ipconfig

ipconfig /?
ipconfig
ipconfig /all

From ipconfig /all, answer: what's the adapter's MAC address (Physical Address)? Is DHCP enabled? Which DNS servers are set?

ScreenshotThe ipconfig /all output with the Physical Address and DHCP lines visible.

9ping and tracert

ping 192.168.1.8
tracert 192.168.1.8

Both reach Win8.1. tracert shows a single hop because the machines share one subnet.

10netstat

netstat -help
netstat -an | more

-a shows all connections and listening ports; -n shows addresses and ports as numbers instead of names. Press Space to page through the output.

11net accounts and net use

net
net accounts
net use

net accounts shows password and lockout policy. net use with no options lists mapped drives. There are none yet.

12Map and remove a network drive

net use * "\\Win8-1\Users\sysadmin\Downloads" /user:sysadmin Train1ng$
net use
net use Z: /delete

The * picks the next free drive letter (Z: here). Run net use to see the mapping, then delete it.

Where people get stuck

The PDF shows this command with curly quotes, which cmd won't accept. Type straight quotes, or use the Copy button here. The computer name is Win8-1 with a hyphen.

ScreenshotThe net use output showing the Z: drive mapped.

13nslookup

nslookup

With no DNS server in the lab, nslookup reports that it can't find the server. On a real network it names your DNS server and lets you query names. Type exit to leave nslookup.

The lab is complete.

    Task 4 - Using Network Command-Line Utilities

    Task 4.1 - Interacting with the CLI

    1 Click the Start button, type cmd. Right-click on Command Prompt listing and click on Run as administrator.

    2 Click Yes to allow the UAC to make changes.

    3 In the command prompt window, type the ipconfig /? command and press Enter to view help for the command. Ipconfig's primary use is finding TCP/IP configuration information, but it has many useful switches that can be considered with the help switch.

    C:\Windows\system32> ipconfig /?

    4 Type ipconfig to view the TCP/IP configuration information. This command will show the current Windows IP configuration.

    C:\Windows\system32> ipconfig

    5 To view more detailed information about the machine's TCP/IP configuration, enter ipconfig /all. What is the MAC address of the local network adapter? Is DHCP being used on this system? What is the DNS server? All these questions and more can be answered with this command. Other ipconfig switches that are useful to use at the CLI when troubleshooting network issues are:  ipconfig /release - sends a message to the server that forces the client to give up its leased DHCP address.  ipconfig /renew - executed to request a new IP address  ipconfig /flushdns - flushes and resets the DNS client resolver cache helpful if you change DNS servers or an IP address assigned to a domain name changes

    C:\Windows\system32> ipconfig /all

    Reference: network tools

    ipconfig

    CommandDoes
    ipconfigAddress, mask, and gateway for each adapter
    ipconfig /allAdds MAC address, DHCP status and server, lease times, DNS servers
    ipconfig /releaseGives back the DHCP address
    ipconfig /renewAsks DHCP for an address
    ipconfig /flushdnsClears the local DNS cache
    ipconfig /displaydnsShows the DNS cache

    ping, tracert, and pathping

    CommandDoes
    ping <host>Four echo requests; shows replies and round-trip time
    ping -t <host>Pings until you press Ctrl+C
    ping -n 10 <host>Sends 10 requests
    ping -4 or -6Forces IPv4 or IPv6
    ping -a <IP>Resolves the address to a name
    tracert <host>Lists each router hop to the destination
    tracert -d <host>Skips name lookups, so it runs faster
    pathping <host>Combines tracert with per-hop packet loss statistics

    netstat

    OptionDoes
    -aAll connections and listening ports
    -nNumbers instead of names
    -bThe program that owns each connection (needs admin)
    -oThe process ID (PID) for each connection
    -rThe routing table
    -eEthernet statistics

    net commands

    CommandDoes
    net useList, map (net use Z: \\server\share), or delete (/delete) drives
    net use Z: \\server\share /persistent:yesReconnect at every sign-in
    net userList or manage local users (Lab 04)
    net accountsPassword and lockout policy
    net shareList or create shares on this PC (Lab 05)
    net view \\computerList a computer's shares

    Other tools you should know

    CommandDoes
    nslookup <name>Queries DNS; nslookup <name> 8.8.8.8 asks a specific server
    hostnameShows the computer name
    arp -aShows the IP-to-MAC table
    route printShows the routing table
    netsh winsock resetRepairs a damaged network stack (restart after)

    Reading an IP address

    On the job

    Work from the PC outward. Each step that passes moves the problem further away.

    StepCommandIf it fails
    1. Is TCP/IP working on this PC?ping 127.0.0.1Reset the stack: netsh winsock reset, reinstall the adapter
    2. Does it have a valid address?ipconfig /all169.254 means no DHCP: check cable, Wi-Fi, DHCP server; try /release and /renew
    3. Can it reach the gateway?ping <default gateway>Local network problem: cable, switch port, VLAN, Wi-Fi
    4. Can it reach beyond the gateway?ping 8.8.8.8Router or ISP problem
    5. Do names resolve?nslookup example.comDNS problem: check DNS servers, ipconfig /flushdns

    Paste the ipconfig /all output into the ticket. The next tech can see the MAC, DHCP server, lease, and DNS without asking the user again.

    On the A+ exams

    Core 1: NetworkingCore 2: Operating Systems

    Core 2 (220-1202) expects you to know these Windows networking commands and when to use them: ipconfig, ping, tracert, pathping, netstat, nslookup, net use, net user, and hostname. Core 1 (220-1201) covers IP addressing, DHCP, DNS, and troubleshooting connectivity.

    High-yield facts

    • A 169.254.x.x address means the PC couldn't reach a DHCP server.
    • ipconfig /flushdns clears stale DNS entries after a server or site moves.
    • tracert shows where along the path packets stop; pathping adds per-hop loss.
    • netstat -an lists connections and listening ports; -b names the program.
    • net use maps drives; /persistent:yes keeps them after restart.
    • Public profile turns sharing and discovery off; Private allows them.

    Check yourself

    1. A PC shows the address 169.254.10.20. What happened?

    It didn't get an address from DHCP and assigned itself an APIPA address. Check the cable or Wi-Fi, the DHCP server, then run ipconfig /release and ipconfig /renew.

    2. Users can reach sites by IP address but not by name. Which tool and what fix?

    It's a DNS problem. Use nslookup to test, check the DNS servers in ipconfig /all, and run ipconfig /flushdns.

    3. You suspect malware is talking to an outside server. Which command shows active connections and the programs that own them?

    netstat -anb from an elevated prompt (or -ano and match the PID in Task Manager).

    4. Write the command to map the share \\fileserver\sales to S: and keep it after reboot.

    net use S: \\fileserver\sales /persistent:yes

    5. Why did tracert show only one hop in this lab?

    All three machines are on the same subnet, so packets go directly to the destination without passing a router.
